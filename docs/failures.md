# Проверка ошибок самой среды

`mutation_report.json` содержит фактические результаты запуска отрицательных
контролей. Повреждаются копии данных и изолированные копии модулей; рабочие
исходники не изменяются. Каждый контроль сначала имеет корректную исходную версию.

| Дефект | Ожидаемое обнаружение |
| --- | --- |
| Подмена FX-курсов | Независимый пересчёт расходится с truth |
| Смещение платежных проводок за границу периода | Меняется независимо выведенный набор ошибок |
| Ошибка суммы эталона на одну минимальную единицу | Несовпадение с пересчётом документов |
| Удаление нарушения | Не исполнены запрошенные количества инъекций |
| Несуществующее доказательство | Ссылка отсутствует в публичных данных |
| Неверная разрядность валюты | Изменяется сумма FX при независимом пересчёте |
| Подмена before в provenance | Не воспроизводится причинная история |
| TP по числу выводов вместо matching | 10 копий одного вывода дают ошибочные 10 TP вместо 1 |
| Отключённая проверка валюты | Дефектный matcher засчитывает 2 TP вместо 1 |
| Truth в первом observation | Проверка допустимых полей обнаруживает закрытый эталон |

Для двух дефектов matcher журнал содержит expected/healthy/mutant TP.
Для повреждённых данных — конкретную ошибку независимого валидатора.
Для утечки — инъекцию закрытого поля в реально исполненный reset.
Это выбранные отрицательные контроли, а не процент покрытия всех возможных мутаций.

При разработке был исправлен отдельный риск: смысловые имена clean/errors в ID
ручных эпизодов заменены непрозрачными идентификаторами. Путь fixture остаётся
доверенной деталью запуска и в наблюдения не попадает. Инвариантность ID проверяет
группа G, доступ к файловой системе — контейнерный probe.

Другой обнаруженный случай: после перестановки проводок корректная политика могла
выбрать иной равнозначный свидетель периода для дублированного счёта. В эталоне
теперь перечислены все допустимые наборы с такими свидетелями; перестановка не
меняет корректность ответа. Регрессия: `test_exponents_offsets_and_alternative_witnesses`.

Ограничения модели перечислены отдельно в `limitations.md`. Проблемы, которые не
проверены тестом, не записываются в отчёте как исправленные.
