# Устройство среды

СЛЕД разделяет три доверенные задачи и один недоверенный процесс. Генератор
создаёт непротиворечивую историю, первичные документы и сбалансированную книгу,
затем применяет адресные изменения. Truth описывает наблюдаемое расхождение,
provenance — исходную книгу и точную последовательность add/update/delete.

Broker `AuditEnv` владеет копией только публичных записей для инструментов.
Он выдаёт страницы до 50 строк, ведёт 100-шаговый бюджет и журнал. Эталон
передаётся отдельному процессу `scoring_worker`; только этот процесс рассчитывает
награду. В закрытом режиме результат остаётся в доверенном launcher до завершения.

Агент запускается отдельным Docker-контейнером: без mounts, сети, Docker socket,
capabilities и прав root, с read-only корнем и ограниченным tmpfs. В образ входят
только клиент протокола, базовые политики и проверочный probe. Кода генератора,
оценщика, данных, seed и эталона в нём нет. JSON-lines сообщения ограничены 4 MiB;
тайм-аут покрывает неполную строку и зависшую запись. Launcher удаляет зависший
контейнер, а не только клиент Docker.

Финансовый валидатор не использует генератор или matcher для вывода нарушений.
Он пересчитывает FX через Fraction и целочисленное округление, тогда как генератор
использует Decimal. Отдельно проверяются исходный баланс, запрошенные количества
ошибок, replay причинных изменений и доступность доказательств. Три ручных
fixtures служат внешними для генератора арифметическими примерами.

Локальный протокол совместим с формой Gymnasium reset/step, но не наследует Env.
Учебные веса, GPU, сетевые API и ключи не нужны. Журналы подходят для последующего
обучения, но улучшение обученной политики в проекте не заявляется.

## Адаптер другой политики

Доверенная сторона вызывает `run_episode(episode, policy='custom', image=...,
policy_command=['python','/app/custom_agent.py'])`. Образ пользовательской политики
заранее собирается организаторами без данных. Не передавайте недоверенные имена
образов или команды от самой политики. Oracle недоступен через агентский протокол.

При старте stdin получает JSON `{observation,reward,terminated,truncated,info}`.
Агент пишет одну строку JSON с действием в stdout; логи направляет в stderr.
После каждого действия получает такое же сообщение. Терминальное сообщение
не требует нового действия. См. `src/sled/agent.py` как минимальный адаптер.

Конкретный entrypoint политик жюри ещё не опубликован в полученных материалах;
адаптация транспорта не меняет финансовые правила или код награды.
